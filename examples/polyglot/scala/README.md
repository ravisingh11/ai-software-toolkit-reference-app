# Scala quality example

This independent Scala 2.13.16/JDK 21 program implements the shared Fieldnotes transition contract. It is a language-specific example: it does not change the deployed Worker. Repositories choose their own tools, thresholds, and enforcement.

From the repository root:

```sh
examples/polyglot/scala/check.sh setup
examples/polyglot/scala/check.sh build
examples/polyglot/scala/check.sh lint
examples/polyglot/scala/check.sh architecture
examples/polyglot/scala/check.sh versions
printf 'example\teditor\talpha\talpha\ttriage\tin_progress\n' | examples/polyglot/scala/check.sh run
printf 'example\teditor\talpha\talpha\ttriage\tin_progress\n' | POLYGLOT_COVERAGE_REPORT="$PWD/.artifacts/polyglot/scala/coverage.xml" examples/polyglot/scala/check.sh coverage
```

The shared repository driver supplies defensive cases and verifies actual results. The application reads six tab-separated fields per line (case ID, role, session workspace, issue workspace, current status, requested status) and returns `case ID<TAB>decision`. It never receives expected results. Empty fields are preserved. Malformed field counts fail the process.

## Tools and scope

- **Build:** the Scala compiler, separately from lint, with fatal compiler warnings.
- **Lint:** [WartRemover](https://www.wartremover.org/doc/install-setup.html), loaded as a compiler plugin. Selected error rules prohibit null, mutable variables, return statements, casts, runtime instance checks, and partial Option/Try access. These are real static analysis rules; ordinary compilation does not enable them.
- **Architecture:** JDK `jdeps` examines freshly compiled class dependencies and rejects any `fieldnotes.domain` dependency on `fieldnotes.cli`. The CLI may depend on the domain. This is a deliberately narrow boundary example, not a complete application architecture policy. The full dependency report is saved under `.artifacts/polyglot/scala/dependencies.txt`.
- **Coverage:** the [JaCoCo agent and CLI](https://www.jacoco.org/jacoco/trunk/doc/cli.html) measure executed JVM bytecode while the shared driver checks the contract. The report converter preserves executable line numbers and covered/uncovered state in Cobertura XML with repository-relative filenames. Hits are binary (executed or not), not invocation counts. Scala-generated bytecode can affect coverage metrics. The raw JaCoCo XML and execution data remain in the artifact directory. A malformed-input adapter branch may remain uncovered by well-formed shared contract cases.

Python 3 and JDK 21 must already exist. Set `JAVA_HOME` for another JDK installation; the script also supports the Homebrew JDK 21 path and PATH lookup. No global tool installation occurs. `setup` is the only networked command and downloads the explicitly versioned jars in `toolchain.json`, verifying SHA-256 before writing them under `.artifacts/polyglot/scala`. Other commands verify those hashes and require setup first. Build, lint, run, coverage, and architecture are offline after setup. This small example invokes compiler jars directly to keep the tool inventory explicit; real applications can configure the same tools through sbt, Maven, or Scala CLI.

Negative verification during development confirmed WartRemover rejects an injected null and the architecture check rejects an injected domain-to-CLI reference. Temporary probes are removed after checking.
